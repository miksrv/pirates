# Pirates

A top-down multiplayer pirate ship battle game. Built with **Phaser 3** for rendering, **React** for the UI shell, and a **WebSocket** server for real-time PvP/PvE combat against bots.

## Features

- **Single player** — battle AI-controlled ships with a full state-machine (patrol/chase/attack/flee), predictive aiming, and dodging.
- **Multiplayer** — authoritative WebSocket server, up to 8 players per arena, FFA with friendly fire, bots fill empty slots.
- **Perks & pickups** — pick a pre-match perk, collect dozens of pickups on the map (speed, damage, armor, shields, mines, an escort fleet, a timed "Leviathan's Fury" mega-buff, and more).
- **Procedural map** — islands generated by rejection sampling with layered coastlines (shallow water → sand → grass → props), no tile grid.
- **Debug panel** — `iddqd` cheat during a single-player match to grant any pickup instantly (dev/testing only, disabled online).

See [Game Mechanics Docs](#game-mechanics-docs) for the full rules.

## Getting Started

### Prerequisites

- Node.js 20+
- npm

### Installation

```bash
npm install
```

### Running Locally

Single player works with just the client. For multiplayer, run the server alongside it:

```bash
# Terminal 1 — game server (WebSocket, port 8081)
npm run server

# Terminal 2 — client dev server
npm run dev
```

The dev client automatically connects to `ws://localhost:8081`.

## Multiplayer Server

- One shared arena is created when the first player joins and torn down when the last leaves; max **8 players**.
- The server runs the authoritative simulation at 30Hz and broadcasts snapshots at 15Hz; clients render 120ms in the past with no client-side prediction.
- Bots always fill the arena: the `BOTS` env var on the server wins (set `0` for pure PvP), otherwise the first joiner's lobby slider is used, otherwise it defaults to 5.
- Sunk ships respawn after 4s with base stats — pickups are lost, perks and kills persist.

Details: [`docs/mechanics/multiplayer.md`](docs/mechanics/multiplayer.md)

## Environment Variables

| Variable          | Used by | Description                                                                 |
|-------------------|---------|-------------------------------------------------------------------------------|
| `PORT`             | server  | WebSocket server port (default `8081`)                                       |
| `BOTS`             | server  | Force a fixed bot count in every arena (`0` disables bots)                    |
| `VITE_SERVER_URL`  | client  | Override the WebSocket URL the client connects to, e.g. `ws://host:port`     |

Production client builds default to `wss://jskit.bugfocus.com/pirates/server` when `VITE_SERVER_URL` is not set.

## Building for Production

```bash
npm run build
```

This type-checks the project and outputs a static bundle to `dist/`. Serve `dist/` with any static file server, and run `npm run server` (or a process manager) for the WebSocket backend.

## Deployment

CI/CD is defined in [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) but is currently **manual-dispatch only** (auto-deploy on push is disabled due to SSH access restrictions on the target server). To deploy manually:

1. Trigger the `Deploy` workflow from the GitHub Actions tab (`workflow_dispatch`), **or** run the equivalent steps locally:
   ```bash
   npm ci
   npm run build
   scp -r dist ecosystem.config.js <user>@<host>:<deploy-path>
   ssh <user>@<host> "cd <deploy-path> && pm2 startOrReload ecosystem.config.js --update-env && pm2 save"
   ```
2. The static client is served via `serve -s dist -l 3010` under PM2 (see [`ecosystem.config.js`](ecosystem.config.js)).
3. The WebSocket server must be run/managed separately (e.g. its own PM2 process) and be reachable at the URL configured via `VITE_SERVER_URL` at build time; a reverse proxy must forward the WebSocket upgrade.
